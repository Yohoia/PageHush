## 任务 1：初来者开始写一篇文章，再从目录找回

1. 阅读欢迎内容。文字明确指出「＋ 新建」打开空白纸，回看文字去「所有文稿」；未在下一步入口上犹豫。
2. 点击顶栏「＋ 新建」。仍在编辑页，标题变为「未命名文稿」，正文空白，有「从一句话开始。」及「新文稿已打开」反馈。
3. 输入标题「午后的书页（走查）」。正文输入二级标题、段落、粗体、引文和两项列表：

   ```markdown
   ## 今天的片刻

   窗边的书页翻到第七页，我决定先写一句话。

   **留住微光**，也留住此刻的安静。

   > 明天再把这段旅程写完。

   - 泡一杯茶
   - 记下新的灵感
   ```

4. 点击「所有文稿」，进入 `#library`。顶部显示 06 篇；新文章位于第一项，展示标题、正文摘录、随笔分类、日期、69 字与「正在写」。
5. 点击该文稿项，回到编辑页。标题和 Markdown 换行、符号完整显示，底部显示「已保存」。任务完成。

操作记录：两次导航点击、标题输入、正文输入、一次列表项打开，无页面路线走错。第一次使用自动化的“设置值”输入多行正文时，观察到换行被折叠且字数未同步，因此改用正常全选、粘贴输入，再从目录和重新打开的正文核实。此项是工具输入方式纠正，不能直接认定为产品缺陷。

## 任务 2：找到雨文章，再按灵感筛选

1. 点击「所有文稿」进入目录，搜索框输入「雨」。页面更新为「搜索结果 / 1 篇文稿」，唯一结果「雨停之后的街道」。
2. 点击结果，进入该文章编辑页。标题和正文第一句「雨停之后，街道比下雨的时候更安静。」确认打开目标。
3. 点击「所有文稿」返回目录。搜索框仍保留「雨」，仍显示 1 篇雨文章。
4. 直接点击「灵感」。分类选中灵感，但搜索词仍在，结果变为 0 篇，出现「没有找到这篇文稿」「换个词，也可以试着搜索正文里的句子。」及「查看所有文稿」。
5. 此处出现一次短暂路线纠正：意识到搜索与分类叠加，需要先清除「雨」。点击「清除搜索」后显示「灵感 / CONTENTS / 1 篇文稿」及「散步时想到的」。
6. 点击「全部」，分类清除，恢复「篇目 / CONTENTS / 6 篇文稿」。任务完成。

实际摩擦：从雨文章返回后直接切换分类，会继承先前搜索而变成空结果。页面同时保留可见搜索词、分类选中态和清除入口，因此能够独立恢复，未卡住；这是一次实际经历的筛选理解成本。

## 任务 3：用正文句子寻找文稿，再恢复全部

1. 在全目录搜索框输入刚刚读到的引文：「同一条街道，每次走过都是不同的一天」。界面显示 1 篇结果「雨停之后的街道」。此句不在目录摘录里，仍被搜索命中。
2. 点击结果打开文章，正文引文中确实有该句。任务属于第二次雨文章查找，使用不同查找线索。
3. 此次使用浏览器“返回”，没有点击应用内「所有文稿」。实际回到 `#library`；原完整句子和 1 篇结果仍在。
4. 全选搜索词，输入「宇宙鲸鱼在冰箱里唱歌」。出现 0 篇结果、无结果解释和「查看所有文稿」。
5. 点击「查看所有文稿」。搜索框为空、全部分类选中，列表恢复 6 篇。任务完成。

操作记录：搜索输入 → 列表项点击 → 浏览器返回 → 替换搜索 → 恢复按钮。未卡住。查找结果摘录没有展示命中的引文，所以仍需打开正文核实完整句子，发生一次确认性阅读，没有误开其他文章。

## 补充：保存失败模拟状态

独立入口：`http://127.0.0.1:4173/design/writing/solo.html?state=error`，另一个自建临时 tab。

1. 初始欢迎文章显示 183 字、「保存失败，草稿已保留」和「重试」按钮。
2. 在正文末尾新增：「保存失败走查：这句新输入需要在重试后保留。」。
3. 编辑后正文实际包含新增句，字数变为 204；保存状态先显示「未保存」，重试按钮同时消失。
4. 下一次界面观察显示「已保存」，新增句仍在。因此无法点击“编辑后重试”：按钮已不再提供。这项不能标记通过。
5. 保存编辑后画面证据，随后明确重新加载模拟入口，回到原 183 字欢迎内容和初始失败状态；此次直接点击「重试」。状态变「已保存」，重试按钮消失，原正文没有变化。这只能证明初始模拟状态的重试路径。

![初始保存失败模拟状态](/Users/yohoia/Desktop/explore-design/design/writing/task-walk-library-error.png)

![编辑后新增句仍在、状态自动变为已保存](/Users/yohoia/Desktop/explore-design/design/writing/task-walk-library-error-edited.png)

可复核结论：模拟失败页允许继续输入且新增文字暂留，初始重试能解除提示；该页面没有让“输入新内容后再按重试”的序列实际发生。要验证真实失败中继续编辑后重试，应提供能持续失败到用户主动重试的测试情境。
