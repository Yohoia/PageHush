# 固定文章地址

日期：2026-10-09。文章工作台统一使用 `/a/:articleKey`。`a` 表示 article，标识为 22 位数字与大小写字母，地址不包含标题。

## 标识与数据

使用既有 `articles.id` 的完整 128 位 UUID 做 Base62 编码，固定补齐到 22 位。编码可逆、一一对应，不截断、不用标题计算，因此不存在新增短码碰撞；修改标题或 slug 不改变短地址。新旧文章都直接适用，不增加数据库字段，也无需数据迁移。

共享实现位于 `packages/shared/src/article-address.ts`。API 的列表、详情、创建和更新响应增加 `shortId`；原有 `id` 与 `slug` 保留。编码不是访问凭证，文章访问仍经过现有访问码会话校验。

## 路由与旧链接

- 网页 `/a/:articleKey` 严格校验长度、字符和 128 位范围，解码成 UUID，调用原有 `/v1/articles/:uuid` 接口。
- 旧 `/articles/:slug`（包括中文）和 `/articles/:uuid` 继续读取文章，成功后 replace 为短地址，保留查询参数、片段和路由 state，不额外增加历史记录。
- 卡片链接、新建文章保存后的跳转使用短地址；修改和删除根据固定 UUID 调用 API。
- 卡片到编辑器的内容预载与封面转场匹配短标识；返回列表仍使用原来的列表快照与滚动位置。
- 旧 slug 仍供既有导入导出与博客发布约定使用。本轮只修改 PageHush 工作台地址，不重命名博客文章文件。

## 拾页与部署

拾页优先使用 API 返回的 `shortId` 打开 `/a/`，保存结果保留 shortId，重开可恢复。旧 API 或旧保存结果没有 shortId 时使用 `/articles/:uuid`，不使用中文标题链接。

先部署网页，再部署 API。网页可以自行从 UUID 生成短地址，因此兼容旧 API；网页已支持 `/a/` 后，API 返回 shortId 才会让拾页使用此路由。部署保留 SPA 路由回退到 `index.html`，保证直接打开和刷新 `/a/` 正常。当前仅修改本机代码，未操作线上数据库或部署。

## 验证

单元检查覆盖 1,000 个随机 UUID、前导零、最大值、完整往返与非法输入；浏览器检查覆盖卡片真实链接、慢响应时预载、刷新、旧中文/UUID 链接替换、查询片段保留、返回历史、重命名保存、新建保存、无效短地址及登录拦截。保留原有封面转场、默认封面与列表返回检查。拾页检查在隔离 Chromium 与模拟 API 中完成，不向线上创建草稿。
